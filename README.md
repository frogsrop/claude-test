# Аудит неврологов СПб (ПроДокторов)

Пайплайн проверки топ-врачей из списка
[prodoctorov.ru/spb/nevrolog](https://prodoctorov.ru/spb/nevrolog/?sort=rating&high_rating=true)
по четырём осям: **накрутка отзывов**, **открытые данные и заслуги**, **компетентность против
рейтинга**, **высказывания в соцсетях/СМИ**. Каждый собираемый факт проходит проверку
идентичности (entity resolution) с порогом уверенности **0.8** — иначе отбрасывается как
возможный однофамилец.

Статус: **пилот на 10 врачах завершён**. Полный прогон на 100 — не запускался.

## Структура

```
pipeline/doctor-audit.js     — скрипт пайплайна (dynamic workflow, 6 стадий)
audit/pilot/_scorecards.json — сводные итоги по 10 врачам
audit/pilot/<id>-<slug>/     — сырые данные по каждому врачу:
    profile.json             — профиль + отзывы с ПроДокторов
    fraud.json               — анализ признаков накрутки
    osint_sci.json           — научный след (публикации, степени, доклады)
    osint_social.json        — соцсети и СМИ
    osint_neg.json           — негатив (жалобы, суды, дисциплинарка)
    statements.json          — разбор публичных высказываний (если найдены)
    scorecard.json           — итоговая карточка
```

Каждый OSINT-файл содержит и `accepted` (identity_confidence ≥ 0.8), и `rejected`
(отброшенные однофамильцы) — видно, что и почему отсеяно.

## Стадии пайплайна

1. **Профиль** — скрейп ПроДокторов: образование, сертификаты (действующие/просроченные),
   места работы, публикации, награды + до ~100 отзывов с датами и оценками.
2. **Отзывы** — признаки накрутки: всплески по датам, шаблонность, распределение оценок,
   конкретика. Только косвенные признаки (нет доступа к аккаунтам), с обязательными
   counter-signals.
3. **OSINT ×3** — параллельно: научный след / соцсети-СМИ / негатив. Entity resolution
   встроен в сбор — у каждого факта скор совпадения по якорям (ФИО+отчество, город,
   клиника, вуз, взаимные ссылки).
4. **Высказывания** — подтверждённые (≥0.8) публичные материалы проверяются против
   доказательной медицины; каждый флаг — только с дословной цитатой и ссылкой.
5. **Проверка скептиком** — каждый негативный вывод отдельный агент пытается опровергнуть;
   опровергнутое не попадает в red flags.
6. **Синтез** — scorecard: вердикт по рейтингу, competence 0–10, red/green flags, confidence.

## Выводы пилота — что чинить перед прогоном на 100

1. **Сбор списка — детерминированно из HTML, не через LLM.** Врач №10 «Новикова» по
   URL из списка оказался **стоматологом**, а не неврологом (настоящий невролог — другой
   профиль, 716443, рейтинг 3.5). LLM-извлечение ссылок ненадёжно → нужен парсинг разметки
   выдачи. **Обязательно.**
2. **Вердикт «слипся»** — 9/10 «скорее подтверждён», шкала не различает. Переписать
   критерии на числа (competence + fraud + актуальность сертификатов). **Обязательно.**
3. **Скептик работает** — опроверг ложные флаги «накрутки» (Тонян, Миночкина) и
   «антинаучности» (иглорефлексотерапия у Коротковой, остеопатия у Филиппова). Оставить.
4. **Источники ограничены** — eLibrary 403, КиберЛенинка часто недоступна, VK/НаПоправку/
   Instagram блокируют без логина. Публикации подтверждались через DOI/Scholar (сработало
   у Тоняна, Терещенко) — добавить Scholar/ORCID/DOI-резолвинг. Улучшение.
5. **Отзывы собираются частично** (20–100 из ≤316) — анализ накрутки идёт по сэмплу.

### Открытый вопрос по политике (нужно решение)

Как трактовать слабо-доказанные, но **лицензированные** методы (рефлексотерапия/иглоукалывание,
остеопатия)? Текущая планка: сам метод — не флаг, флагуется только конкретное ложное/опасное
заявление с цитатой. Альтернативы: (B) мягкий штраф за продвижение недоказанного, (C) жёсткий
флаг. **Влияет на оценку заметной доли врачей списка.**

## Как продолжить

- Скрипт пайплайна: `pipeline/doctor-audit.js` (dynamic workflow — принимает `{dir, doctors:[{slug,url,name}]}`).
- Для сотни: сначала правки №1 и №2 выше, затем собрать список 100 профилей и прогнать.
- Ориентир стоимости: ~3.8M токенов и ~1ч45м на 10 врачей → на 100 примерно ×10.
